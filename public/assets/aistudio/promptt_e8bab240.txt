Lakukan AUDIT, DEBUG, FIX, UPGRADE, dan TESTING menyeluruh terhadap seluruh source code project yang diberikan sampai benar-benar berfungsi. Jangan hanya memberikan analisis atau contoh kode. LANGSUNG kerjakan perubahan pada project dan hasilkan FULL SOURCE CODE yang siap dijalankan.

1. ATURAN UTAMA

- WAJIB mempertahankan "@itsliaaa/baileys" sebagai library WhatsApp utama.
- DILARANG migrasi ke library WhatsApp lain atau menggabungkan implementasi WhatsApp yang berbeda tanpa kebutuhan teknis yang terbukti.
- Session lama BOLEH dihapus dan pairing ulang BOLEH dilakukan jika diperlukan.
- Dependency boleh diperbarui atau diganti jika terbukti bermasalah, tetapi kompatibilitas seluruh project wajib diverifikasi.
- Pertahankan 100% fitur lama, plugin, multi-session/multi-number, command, dashboard Telegram, API, konfigurasi, struktur data, dan alur kerja yang sudah ada.
- DILARANG menghapus fitur, membuat mock sebagai pengganti implementasi produksi, membuat tombol pajangan, endpoint palsu, atau status koneksi statis.
- Pertahankan arsitektur dan desain yang masih berfungsi. Ubah hanya bagian yang diperlukan untuk memperbaiki masalah atau meningkatkan stabilitas.
- Jangan berhenti setelah audit. LANGSUNG PERBAIKI masalah yang ditemukan, kemudian uji ulang.

2. FULL SOURCE CODE AUDIT

Periksa seluruh folder dan file, termasuk:

- Entry point, konfigurasi, "package.json", lockfile, dan seluruh dependency.
- Backend, frontend, API, database, session manager, message router, plugin loader, serta integrasi Telegram.
- Handler pesan, command, event, pengiriman media, autentikasi, dan reconnect.
- Script startup, deployment, Docker/configuration jika memang digunakan, dan GitHub Actions.
- Semua tombol, formulir, endpoint, dan fitur yang berpotensi hanya berupa tampilan tanpa fungsi nyata.

Identifikasi akar masalah, dependency yang tidak kompatibel, fungsi yang tidak dipanggil, error handling yang tidak lengkap, race condition, memory leak, dan fitur yang belum terhubung.

Jangan menganggap project sehat hanya karena server berhasil menyala.

3. WHATSAPP & @itsliaaa/baileys

Pastikan implementasi kompatibel dengan versi "@itsliaaa/baileys" yang benar-benar dipasang.

WAJIB:

1. Verifikasi API, export, dependency, versi Node.js, CommonJS/ESM, dan persyaratan runtime.
2. Periksa mekanisme pengambilan versi WhatsApp Web, pairing QR/code, autentikasi, penyimpanan kredensial, serta event koneksi.
3. Perbaiki pengiriman dan penerimaan pesan, pengiriman media, message acknowledgment jika didukung, serta handler event sesuai API library.
4. Tangani disconnect reason, logout, session invalid, gangguan jaringan, timeout, dan kegagalan pairing secara benar.
5. Implementasikan reconnect dengan exponential backoff, batas percobaan yang terkontrol, dan mekanisme pemulihan yang tidak menghasilkan socket ganda.
6. Cegah reconnect bertumpuk, listener bocor, event ganda, race condition, dan status ONLINE palsu.
7. Pastikan status koneksi berasal dari kondisi socket aktual, bukan nilai statis atau sekadar keberhasilan membuat pairing code.
8. Pertahankan kompatibilitas seluruh plugin dan modul yang menggunakan API library.
9. Jangan mengandalkan versi protokol hardcoded. Verifikasi mekanisme versi yang tersedia dan tangani kegagalannya secara aman.
10. Jika versi fork yang digunakan benar-benar tidak kompatibel, identifikasi penyebab dan perbaiki penggunaan API atau dependency tanpa mengganti library utama.

Jangan mengklaim protokol terbaru sudah didukung jika belum diverifikasi melalui pengujian nyata.

4. SESSION & MULTI-SESSION

Session lama BOLEH di-reset karena prioritasnya adalah membuat project berfungsi kembali.

- Sediakan prosedur reset session yang jelas dan aman.
- Jangan menghapus file project, database, plugin, konfigurasi, atau data pengguna ketika mereset autentikasi WhatsApp.
- Backup data penting sebelum migrasi atau perubahan struktur.
- Pastikan pairing ulang berjalan dan kredensial baru tersimpan dengan benar.
- Uji pemulihan koneksi setelah restart.
- Setiap nomor wajib memiliki socket, kredensial, status, event handler, dan lifecycle masing-masing.
- Pastikan disconnect satu nomor tidak mematikan session nomor lain.
- Perbaiki migrasi session lama jika ditemukan pemetaan user atau direktori yang salah.

5. BACKEND, API, DATABASE & TELEGRAM

Audit dan perbaiki seluruh integrasi:

- Semua endpoint harus menjalankan fungsi nyata, memiliki validasi input, error handling, dan respons yang sesuai.
- Dashboard harus menampilkan status koneksi WhatsApp, nomor aktif, error, dan informasi session berdasarkan data aktual.
- Integrasi Telegram harus mempertahankan mekanisme login/dashboard, command, tombol, callback, serta kontrol yang memang sudah ada.
- Message router dan plugin loader harus berfungsi dengan semua plugin lama.
- Hot-reload plugin tidak boleh membuat handler ganda atau menghentikan bot.
- Pastikan operasi database konsisten, aman dari race condition, dan tidak merusak data.
- Periksa autentikasi dan otorisasi setiap endpoint sensitif.
- Lindungi token Telegram, session WhatsApp, dan kredensial lainnya dari source code, respons API, dan log.

Jangan membuat endpoint status yang selalu mengembalikan ONLINE atau frontend yang menampilkan hasil palsu.

6. DEPENDENCY & RUNTIME

- Pilih versi Node.js yang kompatibel dengan library utama dan dependency lainnya.
- Audit semua dependency secara individual sebelum memperbarui.
- Perbaiki konflik CommonJS/ESM, modul yang tidak ditemukan, API usang, dan dependency native.
- Jangan memperbarui seluruh dependency secara membabi buta.
- Gunakan lockfile yang sesuai dengan package manager.
- Pastikan instalasi bersih berhasil melalui perintah yang terdokumentasi.
- Hapus dependency yang benar-benar tidak digunakan hanya setelah memastikan tidak merusak fitur lama.
- Tambahkan validasi konfigurasi saat startup dan pesan error yang informatif.

7. AUTOMATED TESTING PIPELINE

Implementasikan pipeline nyata berikut:

Nulis Kode
↓
Static Test
↓
Unit Test
↓
Integration Test
↓
E2E Test
↓
Load Test
↓
Build & CI/CD Deploy

Setiap tahap harus memiliki konfigurasi, script, perintah, dan laporan hasil yang benar-benar dapat dijalankan.

A. Static Test

- Gunakan ESLint untuk JavaScript/TypeScript.
- Jika project menggunakan TypeScript, jalankan type-checking.
- Jika project JavaScript murni, gunakan pemeriksaan sintaks dan linting yang sesuai tanpa memigrasikan seluruh project secara paksa.
- Deteksi typo, import rusak, variabel bermasalah, tipe data, dependency tidak valid, dan kesalahan konfigurasi.
- Error yang wajib diperbaiki harus menyebabkan pipeline gagal.

B. Unit Test

- Gunakan framework yang sesuai dengan stack project.
- Uji fungsi, helper, validasi, routing pesan, session manager, reconnect, serta logika plugin.
- Uji kondisi normal, input tidak valid, exception, dan edge case.
- Gunakan mock hanya untuk mengisolasi dependency eksternal.
- Tetapkan target coverage yang realistis, ukur coverage, dan prioritaskan modul penting.

C. Integration Test

- Uji interaksi backend, database, API, session manager, message router, plugin loader, dan integrasi Telegram.
- Gunakan database pengujian atau environment terisolasi.
- Uji validasi data, timeout, error handling, reconnect, dan pemulihan.
- Bedakan hasil mock test dengan pengujian terhadap layanan eksternal yang sesungguhnya.
- Jangan menyatakan integrasi nyata berhasil jika hanya diuji menggunakan mock.

D. E2E Test — Browser Automation

Gunakan Playwright atau framework browser automation yang sesuai jika project memiliki frontend web.

Robot harus benar-benar:

- Membuka browser dan mengakses aplikasi.
- Mengeklik tombol dan mengisi formulir.
- Menguji navigasi, dashboard, pengelolaan nomor, plugin, serta status koneksi.
- Memverifikasi request API, respons backend, dan hasil yang terlihat di UI.
- Menguji kondisi error, loading, empty state, dan kegagalan koneksi.
- Memastikan tombol penting menjalankan tindakan nyata.
- Menyimpan screenshot, trace, serta laporan jika terjadi kegagalan.

Jalankan frontend dan backend pada environment pengujian. Jangan mensyaratkan akun WhatsApp produksi untuk seluruh tes UI; pisahkan E2E lokal dari pengujian pairing dan pengiriman pesan yang membutuhkan akun nyata.

E. Load Test

Gunakan k6, Artillery, atau tool yang sesuai.

- Uji endpoint dengan traffic bertahap dan terkontrol.
- Ukur throughput, latency p50/p95/p99, error rate, serta penggunaan CPU dan memori jika tersedia.
- Evaluasi request bersamaan, kestabilan backend, dan konsumsi resource ketika multi-session aktif.
- Tentukan ambang kelulusan berdasarkan baseline dan kapasitas environment.
- Jangan melakukan spam atau membanjiri layanan WhatsApp/Telegram.
- Jangan menjalankan load test agresif pada production.
- Simpan laporan metrik aktual. Jangan mengarang angka atau menyatakan berhasil tanpa hasil pengukuran.

F. Build & CI/CD Deploy

Gunakan GitHub Actions untuk mengotomatiskan pipeline.

Urutan:

1. Install dependency dari lockfile.
2. Static Test.
3. Unit Test.
4. Integration Test.
5. E2E Test.
6. Load Test terkontrol sesuai kebijakan pipeline.
7. Build/package dan validasi artifact.
8. Deploy hanya setelah seluruh quality gate wajib lulus.

Ketentuan:

- Jalankan pemeriksaan yang sesuai saat pull request dan push ke branch yang ditentukan.
- Gunakan dependency antarjob yang benar agar deployment tidak berjalan sebelum tes wajib selesai.
- Kegagalan tes wajib harus memblokir deployment.
- Jangan menggunakan "continue-on-error" untuk menyembunyikan kegagalan.
- Gunakan cache, timeout, concurrency control, dan artifact laporan dengan benar.
- Simpan token dan kredensial di GitHub Secrets.
- Jangan menaruh secret di source code atau log.
- Batasi deployment production pada branch dan environment yang diizinkan.
- Jika project belum memiliki target deployment, audit arsitekturnya dan sediakan konfigurasi yang sesuai tanpa mengarang target atau kredensial.
- Jika sebuah tes membutuhkan layanan atau secret yang tidak tersedia, tandai BLOCKED/UNVERIFIED dan jangan mengklaim lulus.

Pipeline wajib dapat diulang dan memberikan hasil yang dapat diverifikasi.

8. KEAMANAN & STABILITAS

- Jangan mencetak kredensial atau session ke log.
- Validasi input dan batasi endpoint sensitif.
- Cegah kebocoran data antar-session.
- Tangani error tanpa mematikan seluruh bot jika hanya satu session yang bermasalah.
- Pastikan proses shutdown membersihkan timer, listener, dan socket yang tidak lagi digunakan.
- Jangan menghapus data penting secara otomatis.
- Jangan menyimpan token atau secret langsung di source code.
- Jangan mengirim traffic pengujian agresif ke layanan pihak ketiga.

9. FULL PROJECT DELIVERABLE

Hasil akhir WAJIB berupa project lengkap yang sudah diperbaiki, bukan hanya potongan kode, patch terpisah, prompt lanjutan, atau penjelasan.

Sertakan:

1. Seluruh source code yang diperlukan.
2. "package.json" dan lockfile yang valid.
3. Konfigurasi runtime serta contoh konfigurasi tanpa secret.
4. Seluruh script testing dan konfigurasi framework yang digunakan.
5. Workflow GitHub Actions yang benar-benar menjalankan pipeline.
6. Dokumentasi instalasi, startup, reset session, pairing ulang, testing, dan deployment.
7. Daftar file yang dibuat, diubah, atau dihapus beserta alasannya.
8. Daftar dependency yang diperbarui dan alasan teknisnya.
9. Ringkasan akar masalah dan perbaikannya.
10. Laporan Static Test, Unit Test, Integration Test, E2E, Load Test, build, dan deploy.
11. Daftar tes yang gagal, diblokir, atau belum dapat diverifikasi.

Jika memungkinkan, kemas seluruh hasil akhir dalam ZIP siap diunduh. Pastikan ZIP berisi source code lengkap dan tidak menyertakan "node_modules", kredensial, token, atau session pribadi.

10. FINAL ACCEPTANCE CRITERIA

Project baru boleh dinyatakan selesai jika:

- Instalasi bersih berhasil.
- Server startup tanpa error yang belum terselesaikan.
- Bot dapat dipasangkan dengan WhatsApp menggunakan "@itsliaaa/baileys".
- Pengiriman dan penerimaan pesan berfungsi melalui pengujian nyata.
- Session dapat pulih setelah restart sesuai kondisi autentikasi.
- Multi-session/multi-number berfungsi dan terisolasi.
- Seluruh plugin, command, serta fitur lama tetap berfungsi.
- Dashboard Telegram dan API menunjukkan status aktual.
- Static Test, Unit Test, Integration Test, E2E Test, dan Load Test menghasilkan laporan yang dapat diverifikasi.
- Build dan CI/CD berjalan sesuai konfigurasi.
- Deployment diblokir jika quality gate wajib gagal.
- Tidak ada fitur lama yang diam-diam dihapus atau diganti dengan dummy.

JANGAN mengklaim seluruh kriteria terpenuhi apabila masih ada tes yang gagal atau belum dijalankan.

MULAI DARI AUDIT SOURCE CODE, LANJUTKAN DENGAN PERBAIKAN LANGSUNG, JALANKAN PIPELINE, PERBAIKI KEGAGALAN, DAN SERAHKAN FULL PROJECT FINAL.

1. "@itsliaaa/baileys" tetap digunakan.
2. Seluruh project benar-benar berfungsi.
3. Tidak ada fitur lama yang hilang.
4. Semua pengujian nyata, bukan sekadar formalitas.
5. Deployment hanya setelah quality gate wajib lulus.
